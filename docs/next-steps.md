# 接下来怎么做

## P0：比赛演示前

1. 固化三条可重复演示路径：资料不足进入补件、TKP 120天进入特批、命中无责取消或间接损失后退回修改。
2. 用仓库外的4份比赛合同/订单样本执行回归，保留命中规则和审批路由结果，不提交原始材料。
3. 和队友确认 `credit_policy.json` 中的建议权重与覆盖率阈值，答辩统一口径：“制度条件来自企业材料，权重和阈值是可配置建议模型”。
4. 准备一个本地 OA/SAP/CRM Mock，展示“申请 → 授权审批 → 回写正式额度/账期”的闭环。

## P1：比赛前优先补齐

1. 使用东江测试环境完成OA、CRM和SAP字段映射及端到端联调，校验失败重试和人工补偿。
2. 将 `lifecycle-sweep` 接入企业定时任务，并核对CRM/SAP最近订单、欠款和在手订单口径。
3. Word 修订已完成段落和表格整单元格闭环：风险逐项处置、修订痕迹、清洁版、版本链和重新审查；后续只需补任意 run 级局部修订、批注和客户模板回归。
4. 条款级多语言已支持中/英/越/日/西语，完成片段对齐、原文后插译文、人工确认和双语导出；后续补修改原文后仅重译受影响条款，以及企业术语库/翻译记忆库。
5. 文件证据定位已完成基础版：
   - PDF页码、DOCX段落号、XLSX工作表/单元格、文本行号。
   - 风险卡片点击后在受控查看器显示原文和前后片段。
   - 扫描版PDF逐页OCR已完成；后续补原始PDF画布高亮和历史案件批量重建索引。

## P2：需要东江配合

向企业继续索取以下“接口和规则”，不再追问客户隐私：

1. 泛微 OA 测试环境：流程 ID、表单字段、鉴权方式、回调和附件接口。
2. CRM 测试接口：客户主键、月度订单额、历史逾期、批准额度和账期字段。
3. 正式底线清单：哪些是绝对阻断，哪些允许哪一级授权特批。
4. 信审有效期、额度占用/释放方式、币种、汇率及订单锁定/解锁口径。
5. 5–10 个“合成或完全匿名”的边界案例，只需字段和人工结论，不要客户名称。

## 3–5 分钟演示脚本

1. 30秒：说明痛点——信用与合同割裂、人工逐条核对、敏感信息不能裸发模型。
2. 45秒：上传财报/评级/合同，展示本地解析和脱敏 Trace。
3. 45秒：展示信用分、等级、额度、账期及每个评分依据。
4. 60秒：展示 TKP 120天进入市场总监特批，同时识别不可直接接受的合同条款并给修改建议。
5. 30秒：展示审批路由和 OA/CRM 回写端口。
6. 30秒：展示量化评测与可配置规则，强调可移交、可审计、可扩展。

答辩重点不是“模型多大”，而是：

- 硬规则不会被幻觉覆盖。
- 信审结果真的进入合同审查。
- 敏感数据在模型调用前已经脱敏。
- 结论能够复核、回归测试和接企业系统。
