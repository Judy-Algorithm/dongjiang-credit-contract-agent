# 接下来怎么做

## P0：未来 1–2 天

1. 在自己的电脑运行 `./scripts/run_web.sh`，完整走三遍：
   - TKP 120天账期 → 原则阻断。
   - TKP额度超限但账期未超90天 → 特别审批。
   - TKM尾款50% → 原则阻断。
2. 和队友共同确认 `credit_policy.json` 中的建议权重，答辩统一口径：“底线来自企业，权重是可配置建议模型”。
3. 准备 5–10 份公开制造企业主体评级/年报和自制合同，放在仓库外的演示数据目录，不提交客户资料。
4. 运行 `python3 scripts/evaluate.py`，把结果截图放进效果验证报告。

## P1：比赛前优先补齐

1. Word 保真修订：
   - 风险建议可逐条接受/拒绝。
   - 原文插入修订痕迹。
   - 导出带修订版和清洁版 DOCX。
2. 条款级多语言：
   - 先做中英，再扩越南/日/西语。
   - 原文段落后插入译文。
   - 修改原文后只重译受影响条款。
3. OA/CRM Mock：
   - 做两个本地 Webhook。
   - 演示“读取客户历史 → 提交审批 → 回写额度/账期”。
4. 文件证据定位：
   - PDF页码、DOCX段落号、XLSX工作表/单元格。
   - 风险卡片点击后跳转到原文。

## P2：需要东江配合

向企业继续索取以下“接口和规则”，不再追问客户隐私：

1. 泛微 OA 测试环境：流程 ID、表单字段、鉴权方式、回调和附件接口。
2. CRM 测试接口：客户主键、月度订单额、历史逾期、批准额度和账期字段。
3. 正式底线清单：哪些是绝对阻断，哪些允许哪一级授权特批。
4. 信审有效期、额度占用/释放方式、币种和汇率口径。
5. 5–10 个“合成或完全匿名”的边界案例，只需字段和人工结论，不要客户名称。

## 3–5 分钟演示脚本

1. 30秒：说明痛点——信用与合同割裂、人工逐条核对、敏感信息不能裸发模型。
2. 45秒：上传财报/评级/合同，展示本地解析和脱敏 Trace。
3. 45秒：展示信用分、等级、额度、账期及每个评分依据。
4. 60秒：展示 TKP 120天命中硬底线，同时识别无限责任，定位原文并给修改建议。
5. 30秒：展示审批路由和 OA/CRM 回写端口。
6. 30秒：展示量化评测与可配置规则，强调可移交、可审计、可扩展。

答辩重点不是“模型多大”，而是：

- 硬规则不会被幻觉覆盖。
- 信审结果真的进入合同审查。
- 敏感数据在模型调用前已经脱敏。
- 结论能够复核、回归测试和接企业系统。
