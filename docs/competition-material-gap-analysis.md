# 比赛材料对照与差距分析

更新时间：2026-07-31

## 材料权威等级

| 等级 | 材料 | 使用方式 |
|---|---|---|
| A：业务制度 | 《东江客户信用管理制度（节选）》、销售合同底限条款表 | 决定信用条件、例外机制、审批链和合同风险规则 |
| B：验收样本 | 3份销售合同和1份采购订单 | 验证中英文解析、规则召回和审批路由，不反推制度 |
| C：背景材料 | 东江年报、比赛流程图 | 理解集团业务、角色和演示叙事，不直接生成客户信用结论 |
| D：参考方案 | 外部合同管理产品方案 | 只用于产品能力对标，不作为东江制度依据 |

比赛原始材料保留在仓库外，不进入Git；仓库只保存可公开的规则实现、测试和分析结论。

## 本轮已经落地

- 合同解析或审查无有效结果时默认阻断，消除失败后误放行。
- 信用资料覆盖率与分数分开判断，单一优质评级或单项财务指标必须先补件。
- 信用缓存只按统一社会信用代码或CRM ID复用，不再以企业名称猜测主体，避免同名客户串用。
- 脱敏Vault合并历史映射并原子替换，避免补件/重审破坏可逆映射。
- TKP超过Net 90天、TKM超过40%尾款或半年尾款账期改走特批，符合制度的例外机制。
- 覆盖无责取消、关联主体责任外溢、连带责任、排他、银行承兑、VMI/JIT、间接损失、质保双限和持续供货等比赛底线规则。
- 中文、双语和英文合同完整性识别增强，英文 `exclusive jurisdiction` 不再误报为商业排他。
- 当前未收款与在手订单共同占用授信，合同使用剩余可用额度交叉校验。
- 当前逾期超过30天或已占用超额时锁定合同入口，特别放行必须上传审批证据。
- 合同特批和特别放行附件按SHA-256归档，记录审批人、来源系统和归档时间。
- TKM区分汽车及标准业务、精密模具业务，首期采购豁免、尾期条件和总信用额分别记录。
- 一年无新订单且无欠款、无在手订单时授信清零并转 `Inactive`，支持命令行定时扫描。
- 原始信用资料和合同按案件、类型和SHA-256持久归档，临时上传文件解析后删除。
- OA审批链、批准范围、有效期和证据ID进入案件状态；OA/CRM/SAP HTTP适配器支持鉴权、幂等和结果审计。

## 尚未实现或待企业联调的能力

| 优先级 | 能力 | 当前缺口 | 建议验收 |
|---|---|---|---|
| P1 | 企业系统联调 | HTTP适配器、OA回调和审计已实现，缺真实地址/鉴权/字段字典 | 东江测试环境完成OA发起与回调、SAP/CRM写入验收 |
| P1 | 生命周期数据源 | 清零规则已实现，本地最近订单和欠款字段仍靠录入 | 接SAP/CRM最近订单、应收和在手订单字段，定时任务验收 |
| P1 | 归档治理 | 原件哈希归档已实现，缺企业访问控制和保留期基础设施 | 接对象存储、IAM、保留期和删除审批 |
| P2 | 条款定位 | 规则引用文本片段，缺页码/段落/单元格坐标 | 风险卡可跳转到PDF页、DOCX段落或XLSX单元格 |
| P2 | LLM增强 | 文本网关可选，尚无结构化条款提取节点 | 仅传脱敏文本，JSON Schema校验，失败回退规则链 |

## 推荐开发顺序

1. 获取东江测试环境参数，完成OA/SAP/CRM字段映射与真实联调。
2. 将客户生命周期扫描接入定时任务，并用SAP/CRM真实数据校准清零口径。
3. 最后补条款定位、Word保真修订和多语言；这些提升体验，但不应挤占制度正确性的工期。
