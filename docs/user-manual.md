# 东江一体化信审与合同评审 Agent 操作说明书

> 适用版本：当前比赛技术原型
>
> 重要声明：本系统用于比赛演示和流程验证，不构成法律意见、审计意见或东江集团正式信用政策。`credit_policy.json` 中的评分权重、分数阈值和资料覆盖率是比赛建议模型，正式上线前必须由东江财务、法务、信息安全和业务部门确认。

## 1. 系统是做什么的

系统把“客户信用审核”和“合同审核”串成一条可追踪流程：

```text
发起信审 → 读取/脱敏资料 → 生成信用建议 → 人工审批生效
    → 上传合同 → 金额/账期/付款条件校验 → 法律风险识别
    → 正常通过、特批、财务法务复核，或退回修改
```

系统不会自动签署合同，也不会自动扩大授信。模型只负责形成可解释的建议，正式额度和账期必须由授权人员确认。

### 1.1 两个阶段

1. **信用阶段**：录入客户身份、业务类型、订单额、财务数据、评级和历史合作数据。系统计算信用分、风险等级、建议额度、建议账期、资料覆盖率及信用占用。
2. **合同阶段**：只有信用审批已生效，才允许上传合同。系统提取合同金额、授信额度、账期、TKM 尾款条件等，并检查合同底线条款。

### 1.2 数据安全边界

- 原始信用资料和合同先在本地解析。
- 客户名称、金额、电话、账号等敏感信息在调用外部模型前替换为稳定令牌。
- 外部模型只能接收脱敏文本；脱敏映射保存在本地。
- 特批和特别放行附件保存 SHA-256、上传人和时间，便于审计。

## 2. 启动和停止

### 2.1 Windows PowerShell 启动

在项目目录执行：

```powershell
cd E:\信用评审项目\dongjiang-credit-contract-agent
python -m pip install -e .
python -m dongjiang_agent.cli serve --host 127.0.0.1 --port 8765
```

浏览器打开：`http://127.0.0.1:8765`

首次打开会进入“初始化管理员”。填写管理员姓名、用户名和不少于10位且同时包含字母与数字的密码。该入口只在系统没有任何用户时开放，完成后不能再次初始化。

用户可以在登录页提交昵称、用户名、邮箱和密码完成注册。提交前必须先点击“发送验证码”，输入邮件中的6位验证码；验证码10分钟内有效、最多尝试5次且只能使用一次，重新发送有60秒冷却。邮箱验证通过后账号立即启用，默认角色为业务经办人，无需管理员审核，也不会要求首次登录修改密码。管理员可在“用户管理”页面修改昵称、用户名、邮箱和角色，停用账号或重置密码。绑定邮箱的启用账号可以通过“忘记密码”使用6位邮件验证码重置密码，重置后原会话立即失效，新密码可直接用于登录。

登录后的顶部导航包含“通知”入口。通知中心只保存标题、摘要、业务链接和已读时间，不保存合同原文或附件；点击通知会先标记已读，再跳转到对应案件或运维页面。

系统会按照 `sla_policy.json` 为信用审批、补件、特别放行、合同上传、合同修改、管理层审批和财务法务复核计算目标完成时间。案件列表显示剩余或逾期小时数，案件详情显示截止时间。后台默认每15分钟扫描一次临期/逾期待办，同一案件、同一节点、同一级别只发送一次提醒，节点重新进入后才会产生新的提醒周期。管理员可在“时效运营”页查看逾期明细和节点积压，并手动执行扫描。当前阈值属于比赛建议值，不是东江正式 SLA。

“管理分析”按照案件 Trace 重建节点进入与离开时间，可选择近7天、30天、90天或全部。页面展示发起案件、办结率、平均办结时长、节点SLA达标率、趋势和责任队列积压。CSV包含节点明细；Excel包含“管理摘要”“节点明细”“案件明细”三个工作表。时间范围按案件发起时间筛选，节点达标率只统计能够重建完整进入和离开时间的已完成节点；仍在处理中的节点计入当前积压和逾期数。旧案件若缺少对应Trace，只展示案件级信息，不虚构处理时长。

“Agent运维”仅对管理员开放，按案件汇总信用信审和合同审查子 Agent 的运行健康。严重异常包括计划完整性失败、执行计划与结果不一致以及节点失败；需要关注包括AI证据降级、规则回退和重试。Plan 1.x或没有冻结哈希的旧案件显示为“历史计划”，用于衡量治理迁移覆盖率，不会误报为篡改。点击“查看运行”会直接打开对应案件的“Agent运行”页签。页面只返回计划状态、任务计数和12位摘要，不包含节点输入输出、合同正文、完整哈希或密钥。

严重异常或需要关注的计划可以建立异常单。操作顺序通常是“确认异常 → 分派责任人 → 候选重跑（需要时）→ 关闭”：

1. “确认异常”记录管理员已接手，并自动把当前管理员设为责任人。
2. “分派”选择一个启用账号，系统向责任人发送站内通知，并在已配置邮件时同步邮件提醒。
3. “候选重跑”只列出允许重跑的分析节点，必须填写处理说明。系统在隔离副本重新执行该节点、结果汇总和独立核验；候选结果只供排查，不修改正式授信、合同结论、审批状态或待办。
4. “关闭”必须填写处理说明。确认异常原因及候选核验结果后再关闭；关闭不会自动采纳候选结果。

确定性评分、业务决策、独立核验、人工审批和 OA/CRM/SAP 回写都不会出现在候选重跑清单。如正式结论确需变化，应回到案件业务流程，通过补件、合同修订或正式审批完成，不能从运维页面绕过权限。所有确认、分派、候选重跑和关闭操作都会写入案件 Trace 与安全审计。

系统会自动扫描以下异常：冻结计划完整性失败、计划执行与独立核验结果不一致、节点失败，以及分析节点多次尝试后仍降级或同一计划存在多个降级分析节点。一次重试后成功的健康节点不会自动开单。异常采用“计划号 + 问题类型 + 受影响节点”的指纹去重；相同事实关闭后不会重复出现，只有异常事实变化才会建立新单。

每个自动异常单分别跟踪响应和解决时限。严重异常建议2小时内响应、24小时内解决；需要关注异常建议4小时内响应、48小时内解决。“确认异常”或“分派”完成响应计时，“关闭”完成解决计时。临期和逾期提醒按异常、阶段和级别去重。以上时限来自 `agent_operations_policy.json` 的比赛建议配置，不代表东江正式运维制度。管理员可点击“立即扫描”手动触发，后台默认每15分钟自动扫描一次。

停止服务时，在运行窗口按 `Ctrl+C`。

### 2.2 检查配置和运行测试

```powershell
python scripts\check_hkgai_config.py
python -m unittest discover -s tests -v
python -m compileall -q dongjiang_agent tests scripts
```

配置检查只显示“是否已设置”和模型 ID，不会打印密钥。API 密钥只放在本地 `.env`，不要写入文档、代码或 Git。

如需启用合同 AI 辅助审查，在 `.env` 中设置：

```text
DONGJIANG_AI_ASSISTANCE_ENABLED=true
```

系统只会发送已在本地完成可逆脱敏的合同文本，并要求模型返回结构化 JSON。
AI 辅助发现显示在案件详情的“合同审查”标签中，与制度规则风险分开；AI 不能批准、
拒绝或改变审批路线。接口不可用、返回格式不合规或未检测到脱敏标记时，系统会自动
回退到制度规则审查并留下调用状态。

当 AI 辅助发现能够定位到文档片段时，卡片会显示“第 N 页/段/行”按钮。点击后，
右侧原文证据查看器会打开对应片段及上下文。移动端点击后会自动滚动到证据查看器。

管理员还可进入“Agent运维”查看文本模型健康状态，点击“探测文本模型”执行主动检查。`健康` 表示配置模型存在且接口可达；`未配置` 表示尚未填写密钥；`不可用/异常` 时，先检查 `.env` 的地址、模型 ID 和密钥，再确认启动进程没有残留旧变量。健康记录不会保存密钥、提示词或资料正文。

### 2.1 AI结构化提取操作

案件停在信用审批或合同审批节点时，授权人员进入“Agent运行”：信用字段由信用、财务或管理员处理，合同字段由财务、法务或管理员处理。点击“生成信用字段”或“生成合同字段”后，系统只向外部模型发送本地已脱敏片段，并按以下顺序处理：字段白名单与类型校验、证据片段定位、独立核验、人工处置。

候选卡片显示字段、建议值、置信度和证据位置。先点击证据位置核对原始资料，再勾选准确候选并填写理由：

1. “采纳所选字段”会写入正式业务字段，重新执行分析、评分、审查和独立核验，并生成新的冻结计划；案件仍停留在原审批节点，必须继续人工审批。
2. “拒绝候选”只记录人工决定，不修改任何正式字段。
3. 如果采纳会改变当前审批路由，系统会拒绝直接写入，要求回到正式重审流程。

不要把置信度当成真实性证明。没有证据定位、独立核验失败或超出白名单的字段不会进入可采纳清单；客户名称、账号、电话、邮箱和金额不作为结构化候选。

| 页面 | 用途 |

| 登录 `/login` | 使用管理员创建的内部账号登录 |

案件号通常形如 `DJ-XXXXXXXXXX`。处理案件时只认页面上的“下一步”按钮，不要跳过当前待办直接上传合同。

### 3.1 角色权限

| 角色 | 主要权限 |
| --- | --- |
| 销售 | 发起信审，处理本人案件的补件、合同上传和合同修订 |
| 信用管理/财务 | 审批信用建议，要求补件或拒绝申请 |
| 法务/财务 | 处理合同人工复核 |
| 市场总监 | 处理特别放行和管理层授权事项 |
| 集团管理层 | 处理需要集团授权的合同例外 |
| 系统管理员 | 用户、角色、安全审计和全局业务管理 |

页面会隐藏无权限的处理按钮，服务端仍会再次校验真实登录身份。知道接口地址不能绕过权限。

### 3.1.1 管理员切换账户

系统管理员可以在右上角账户二级菜单点击“切换账户”，选择任一启用的业务账号后，以该账号的单一角色权限查看待办和处理比赛演示流程。切换不需要目标账号密码，刷新页面后仍保持当前模拟账号；可继续切换到另一个业务账号，或点击“返回系统管理员”恢复管理员权限。

模拟期间页面顶部持续显示“管理员模拟”，不能修改目标账号密码。安全审计、案件审批记录和工作流执行信息会同时记录有效业务账号与真实系统管理员，不能把管理员模拟理解为该用户本人登录。普通用户没有账户切换接口权限。

### 3.2 回写失败处理

只有管理员能进入“回写运维”。页面只列出 `failed` 状态，不把“未配置”误报为失败。
点击“重试”只重新调用选中的 OA、CRM 或 SAP，不重新执行审批流程，也不重复调用已经
成功的系统。系统沿用原案件号与回写阶段生成的幂等键，并记录操作人、时间、结果和
历次重试。若错误未消失，记录继续保留在运维列表中。

新案件默认归属发起申请的销售。管理员可以进入案件详情，点击页面右上角的“负责人”按钮，将案件改派给另一个启用的销售账号。补件、合同上传和合同修订会立即进入新负责人的“我的待办”；信用、财务、法务和管理层审批仍按角色分发。

### 3.2 状态含义速查

| 页面状态 | 含义和下一步 |
| --- | --- |
| 草稿/审核中 | 案件刚创建或资料正在解析，等待系统完成处理 |
| 等待信用审批 | 模型建议已生成，由信用管理/财务审批或要求补件 |
| 等待补充信用资料 | 覆盖率或有效维度不足，销售补充资料后重新评估 |
| 授信已生效 | 正式额度和账期已确认，等待上传合同 |
| 信用控制已锁定 | 当前逾期超过30天或占用超过批准额度，等待特别放行 |
| 等待特别放行 | 授权管理层上传证据并批准/驳回本次放行 |
| 等待上传合同 | 销售可以上传合同进入合同审核 |
| 等待管理层审批 | 合同存在超额、超账期或其他可授权例外 |
| 等待财务法务复核 | 条款缺失、评级冲突或中风险事项需要人工判断 |
| 等待修改合同 | 命中硬底线，销售修改后重新提交 |
| 已通过/已特批通过/已复核通过 | 合同审核完成，分别代表正常、授权例外或人工复核通过 |
| 已阻断/已驳回/已关闭 | 风险不可接受、信用申请被拒或业务主动关闭 |

## 4. 发起信审：逐步操作

### 第一步：客户与本次合作

进入“发起信审”，填写带 `*` 的必填项：

- **客户名称**：合同和 CRM 中的正式名称。
- **统一社会信用代码**：强烈建议填写。系统用它匹配历史有效授信；只有企业名称时不会自动复用同名企业额度。
- **CRM 客户编号**：有就填写，方便后续回写。
- **客户类型**：新客户或存量客户。新客户默认不启用历史合作维度，但仍要求至少两个有效评分维度。
- **业务类型**：`TKP` 或 `TKM`。它决定账期、尾款和额度规则。TKM还需选择“汽车及标准业务”或“精密模具业务”。
- **TKM首期采购款豁免**：勾选表示申请未收回首期款即可采购项目物料；它必须作为独立信用条件批准，不能由总信用额自动推导。
- **项目或产品名称**：填写本次项目、产品或模具名称。
- **预计月度订单额**：用于计算授信额度。缺少该字段不能形成可执行额度。
- **本次订单/预计合同金额、申请信用额度、申请账期**：用于记录本次申请；合同上传后还会以合同正文重新提取并校验。
- **申请说明**：说明合作背景、终端项目、担保、预付款或特殊条件。

点击“保存草稿”只保存到当前浏览器的 `sessionStorage`，换浏览器或清理会话后不会保留；确认无误后点击“下一步”。

### 第二步：信用资料

数字字段按页面显示的单位填写：

| 页面字段 | 怎么填 | 作用 |
| --- | --- | --- |
| 注册资本（元） | 例如 `80000000` | 企业基础维度 |
| 成立年限 | 例如 `15` | 企业基础维度 |
| 资产负债率（%） | 填 `45`，不要填 `0.45` | 财务维度；页面会自动转换为 `0.45` |
| 净利率（%） | 填 `10` | 财务维度 |
| 流动比率 | 例如 `1.5` | 财务维度 |
| 营收增长率（%） | 填 `10` | 财务维度 |
| 合作年限 | 存量客户可填，例如 `3` | 合作维度 |
| 近12个月逾期次数 | 例如 `0` | 合作维度 |
| 近12个月最长逾期天数 | 例如 `15` | 合作维度和硬风险判断 |
| 按时付款率（%） | 填 `98` | 合作维度 |
| 当前未收款金额（元） | 当前已出货但未收款金额 | 信用占用 |
| 在手已入单金额（元） | 尚未结算的在手订单 | 信用占用 |
| 当前未收款最长逾期（天） | 当前账款实际逾期天数 | 超过30天锁定 |

第三方评级可填写最多三条评级记录，包括机构、评级、展望和日期。多家评级冲突时，系统默认采用调整后分数较低的一条；分差达到政策阈值时进入人工复核。

上传财报、评级报告、审计报告或历史交易资料。支持 TXT、Markdown、DOCX、PDF、XLSX、CSV、PNG、JPG；单文件不超过15MB，单次请求不超过30MB。

### 第三步：确认提交

核对客户、业务类型、月度订单额、评级、当前占用和逾期信息，点击“提交信用审核”。提交后进入案件详情页。

## 5. 读懂信用结果

案件详情的“信用结果”标签中重点看以下项目：

- **模型信用分/风险等级**：当前建议结果。低风险为 `>=75`，中风险为 `55–74.99`，高风险为 `<55`。
- **资料覆盖率**：资料支持程度，不等于信用分。覆盖率低于45%、有效维度少于2个或缺少月度订单额时会要求补件。
- **建议授信额度**：默认是 `月度订单额 × 风险等级月份系数`。TKP 低/中/高风险分别为3/2/1个月；TKM 为2/1.5/1个月。
- **建议账期**：TKP 低/中/高风险分别为90/60/30天；TKM 还会显示尾款比例和尾款期限建议。
- **TKM子类型条件**：汽车及标准业务的制度基线是离厂后60%分半年/一年收回；精密模具业务是走模后不超过40%且半年内收回。总信用额仍控制同一客户的未收尾款和在手订单合计。
- **当前已占用**：`当前未收款 + 在手已入单金额`。
- **当前可用额度**：`批准额度 - 当前已占用`，低于0时按0显示。
- **信用控制锁定**：当前逾期超过30天，或占用超过批准额度时锁定合同入口。
- **缺失资料/评估说明**：说明哪些字段缺失、为何补件，以及评分采用了哪些信息。缺失值不会被当成0分。

### 5.1 处理信用审批

点击“处理信用审批”，由信用管理或财务人员选择：

- **批准**：按模型建议形成正式授信。
- **调整后批准**：填写正式额度和账期；正式值以人工填写为准，并受最长账期限制。
- **要求补充资料**：将案件转为“等待补充信用资料”。
- **拒绝**：结束信用申请。

注意：点击“批准”后不一定马上开放合同。如果当前逾期或额度占用触发锁定，会进入“信用控制已锁定”，等待特别放行。

## 6. 合同阶段：上传和处理

### 6.1 上传合同

当状态为“等待上传合同”时，销售点击“上传合同”，选择 TXT、MD、DOCX、PDF，或直接粘贴合同正文。合同建议至少包含：

1. 合同主体；
2. 合同标的/技术要求；
3. 金额与付款；
4. 违约责任；
5. 知识产权；
6. 保密；
7. 解除与终止；
8. 法律适用与争议解决。

系统会提取合同金额、授信额度、账期、TKM 尾款比例和尾款期限，并与正式授信的剩余可用额度交叉校验。

### 6.2 合同结果的四种走向

- **已通过**：没有需要阻断、特批或人工复核的事项。
- **等待管理层审批**：超当前可用额度、TKP 超过Net 90天、TKM超常规尾款条件，或其他要求授权的高风险事项。管理层批准时必须上传邮件、OA截图或批准文件。
- **等待财务法务复核**：关键条款缺失、评级冲突或中风险条款需要人工判断。
- **等待修改合同**：命中硬底线，例如买方无责任取消、关联主体责任外溢或间接损失。销售修改合同后点击“重新提交”。

### 6.3 逐项修订与重新送审

案件处于“等待修改合同”时，点击“修改合同”。对每个具有行号或段落号的风险项选择：

1. **采用标准建议**：使用系统内置的东江谈判基线条款；
2. **人工修改**：填写替换后的完整条款；
3. **保留并说明**：保留原文并填写原因，供后续人工谈判或审批复核。

点击“生成修订版本”后，系统同时生成带 Word 修订痕迹版和清洁版。先下载核对，再点击“用清洁稿重新送审”；系统将清洁版作为新合同版本归档、解析并重新执行全部信用和合同规则。原合同不会被覆盖，案件详情的“合同审查”页会长期保留修订版本链。

自动修订支持 TXT、Markdown，以及段落或表格单元格可定位的 DOCX。系统会保留 Word 表格结构、合并单元格和未修改单元格；PDF 或需要精确保留任意局部 run 格式的合同，继续使用“上传人工修订版本”通道。

案件详情分为“概览、信用评估、合同审查、Agent运行、审批记录、原始资料、系统回写”七个页签。合同审查页采用风险清单与原文查看器联动：点击风险项右上角的定位按钮，右侧会显示对应 PDF 页码、DOCX 段落或表格行列、XLSX 工作表/单元格或文本行号，并同时展示前后片段。建议逐条核对，不要只看最终状态。

### 6.4 扫描件、Word 表格和多语言合同

上传扫描版 PDF 后，系统会先逐页提取原生文字，只对没有文本层的页面执行 OCR。案件“原始资料”页会显示 `OCR N 页`；点击文件后可以查看页码、OCR 提取结果、平均识别置信度和降级提示。低清、倾斜、手写、印章遮挡或复杂双栏版式仍需人工核对，OCR 结果不会绕过审批。

Word 表格按“表格号、行、列”建立证据坐标，并记录跨行、跨列信息。风险落在表格条款时，可以像普通段落一样点击定位；案件等待修改时，可以对整个单元格条款采用标准建议或人工替换，输出文件仍保留原表格。

需要合同翻译时，进入案件“合同审查”页下方的“多语言合同”：

1. 选择已解析合同和目标语言（中文、英文、越南语、日语或西班牙语）；
2. 点击“生成对齐译稿”；系统只发送本地脱敏后的片段，并校验模型是否完整保留片段 ID 和脱敏令牌；
3. 点击“复核译稿”，逐段对照原文并直接修改译文；
4. 填写人工复核说明，点击“确认并生成双语稿”；
5. 在版本列表下载双语 Word。原 DOCX 会在原段落或单元格后插入译文，其他格式会生成逐段对照稿。

未确认的翻译草稿不能下载为正式双语稿。翻译稿不会覆盖原合同，也不会改变合同风险、审批状态或授信结论；法律效力仍以签署原文为准。文本模型未配置或调用失败时，系统会明确报错，不会伪造翻译成功。

“Agent运行”页显示父流程、信用信审子 Agent 和合同审查子 Agent 的实际任务计划。每个节点展示完成状态、耗时、执行器、尝试次数、幂等短标识、证据门槛、输入摘要和输出摘要；“并行分析、结果汇总、确定性决策、独立核验”按泳道分组。

计划头部的“计划已冻结”和12位规范摘要用于确认执行期间没有被修改；信用规则、合同规则、模型和提示词版本用于解释同一案件为什么在不同时间可能形成不同计划。“已复用”表示节点命中了本地执行缓存，没有再次调用模型或规则引擎；“证据降级”表示AI发现的原文定位率不足，未定位发现已剔除，制度规则仍正常执行。底部“执行偏差审计”若显示“发现偏差”，可查看缺失、越权、重复或证据违规任务；系统会自动转补件或人工复核，不能继续自动放行。

这里仅显示脱敏或结构化摘要和截断后的哈希，不会显示合同全文、客户敏感字段、脱敏映射、完整哈希或API密钥。动态计划只负责选择分析任务，不能修改审批权限、授信政策或直接批准案件。

只有本轮重新上传并解析的文件具有结构化片段索引。历史案件的旧文件会显示“历史文件需重新解析”，需要重新上传合同或资料后才能使用原文定位。预览接口只允许按当前案件中的文档 ID 读取归档片段，不会向浏览器暴露服务器文件路径。

## 7. 各角色怎么操作

| 角色 | 主要操作 |
| --- | --- |
| 销售 | 发起信审、上传信用资料、上传/修改合同、关闭不再推进的案件 |
| 信用管理/财务 | 审核模型建议、调整正式额度和账期、要求补件或拒绝信用申请 |
| 市场总监/CEO | 审批超额、超账期、TKM尾款例外和特别放行，并上传批准证据 |
| 法务/财务复核 | 处理缺失条款、评级冲突和人工复核，确认通过、补件或要求修改 |

当前 Web 演示页面按待办自动展示按钮；内部工作流还会校验角色权限。没有对应角色时不能代替审批。

## 8. 审批附件与案件资料

特批或特别放行点击“批准”时必须上传至少一个附件。系统会记录：

- 附件原名和用途；
- SHA-256 摘要；
- 文件大小；
- 审批人、来源系统和归档时间。

附件归档在 `data/evidence/DJ-案件号/`。信用资料和合同原件先复制到 `data/archive/DJ-案件号/credit|contract/`，记录SHA-256后才进入解析；临时上传文件随后删除。案件状态、脱敏映射、节点执行缓存和报告分别位于 `data/cases`、`data/vault`、`data/executions` 和 `output`；这些目录可能包含敏感数据，已加入忽略规则，不要提交到 Git。

超过一年无新订单且当前未收款、在手订单均为0时，案件库在读取或执行 `python -m dongjiang_agent.cli lifecycle-sweep` 时会把最新有效授信清零并转为 `Inactive`。若配置了企业接口，命令会同步把清零结果回写OA、CRM和SAP；重新申请时必须补充本客户与东江的历史交易及付款记录。

OA、CRM和SAP接口通过 `.env` 中的 `DONGJIANG_*` 地址、令牌和可选请求头配置。未配置时状态明确为 `not_configured`；调用失败时记录 `failed` 和错误原因。真实OA信用审批回调使用 `POST /api/integrations/oa/callback/{案件号}`，请求头必须包含 `X-OA-Callback-Token`，并提交完整审批链、批准范围、有效期和OA证据ID。

### 8.1 比赛演示的企业系统Mock闭环

在本地 `.env` 设置以下配置并重启服务：

```text
DONGJIANG_INTEGRATION_MODE=mock
DONGJIANG_MOCK_ENTERPRISE_ROOT=data/mock-enterprise
```

用管理员账号打开一个“等待信用审批”的案件，进入“系统回写”，点击“运行 Mock OA 审批”。完成后应看到申请人和四级审批链、批准范围、有效期、Mock OA证据ID，以及 OA、CRM、SAP 三项 `succeeded` 回写。重复调用会复用幂等键，不会伪造第二笔业务写入；记录只保存允许字段摘要，不保存正文或客户名称。

所有 Mock 响应都带 `mock: true`，页面按钮也明确写着 Mock。这只是比赛演示的端到端闭环，不能作为真实泛微OA、CRM或SAP联调证明。生产环境必须清空 `DONGJIANG_INTEGRATION_MODE`，配置真实接口地址和鉴权后再做联调验收。

流程完成后，可在案件详情查看处理记录、原始资料和系统回写；需要机器可读或打印版结果时，查看 `output/DJ-案件号/audit-result.json` 和 `output/DJ-案件号/audit-report.html`。浏览器只展示业务字段和按权限读取的单个原文片段，不展示内部 LangGraph trace、脱敏映射或归档磁盘路径。

## 9. 常见问题

**为什么有 AAA 评级还要补件？**

评分和资料充分度分开判断。只有一个外部评级维度时，不能仅凭单一优质指标形成有效授信；请补充财务或企业基础资料。

**为什么批准额度不是模型建议额度？**

信用人员可以“调整后批准”，正式额度和账期以审批时填写的值为准。

**为什么已批准但不能上传合同？**

通常是当前逾期超过30天或授信占用超过批准额度，状态会显示“信用控制已锁定”。请由授权管理层上传特别放行证据。

**为什么合同被退回，而不是让管理层特批？**

无责任取消、责任外溢、间接损失等属于当前底线阻断项，必须修改合同；超额或超账期才通常进入特批。

**上传失败怎么办？**

检查文件格式、单文件15MB和请求总量30MB限制；PDF/DOCX无法读取时，可粘贴合同正文或补充可读版本。

**如何关闭案件？**

在补件、上传合同或修改合同页面点击“关闭案件/关闭申请”。关闭后不会继续推进当前流程。

## 10. 命令行案件（开发/回归使用）

准备一个 JSON 文件，例如 `case.json`：

```json
{
  "customer": {
    "customer_name": "示例客户",
    "customer_type": "new",
    "business_type": "TKP",
    "project_name": "精密组件项目",
    "monthly_order_amount": 1000000,
    "external_rating": "AA",
    "asset_liability_ratio": 0.45,
    "current_ratio": 1.5
  }
}
```

运行：

```powershell
python -m dongjiang_agent.cli audit --case case.json --output output --no-cache
```

命令行接口适合回归测试；正式业务人员优先使用 Web 页面。真实企业资料、API 密钥和比赛原始材料不要放进示例文件或 Git。
